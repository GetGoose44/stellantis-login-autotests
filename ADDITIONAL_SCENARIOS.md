# Дополнительные сценарии для формы авторизации

Помимо четырёх обязательных сценариев, для формы логина стоит дополнительно проверить:

## Функциональные
- Вход с валидными логином и паролем — успешная авторизация и редирект в личный кабинет/дашборд.
- Вход с email в разном регистре (`User@Mail.ru` vs `user@mail.ru`) — должен матчиться независимо от регистра.
- Вход с лишними пробелами по краям email/пароля (trim на бэкенде).
- Множественные неудачные попытки входа подряд — есть ли блокировка аккаунта / rate limiting / капча после N попыток.
- Поведение при истёкшей сессии / повторном логине в уже открытой сессии в другой вкладке.
- Работа кнопки "Войти" по нажатию Enter в поле пароля (не только по клику мышью).
- Долгий email (граничные значения по длине, лимиты полей на бэкенде).
- SQL-инъекции / XSS-пейлоады в полях логина и пароля (`' OR '1'='1`, `<script>...`) — форма не должна ломаться и не должна пропускать вход.
- Вход учётной записью, заблокированной администратором / уволенным сотрудником.
- Устойчивость к CSRF (валидность/просрочка скрытого токена `_csrf`, повторная отправка формы с протухшим токеном).

## UI/UX
- Фокус переходит на первое невалидное поле после неуспешной отправки формы.
- Placeholder и лейблы не съезжают/не перекрываются при длинном тексте.
- Состояние кнопки "Войти" (disabled/спиннер) во время запроса — защита от двойной отправки по двойному клику.
- Отображение формы на разных разрешениях экрана (мобильная версия, планшет).
- Корректная работа переключателя языка (РУС/ENG) — тексты ошибок и лейблы тоже переключаются.
- Автозаполнение браузером (autofill) не ломает валидацию и маскировку пароля.

## Безопасность/инфраструктура
- Пароль никогда не передаётся и не логируется в открытом виде в сетевых запросах/консоли/localStorage.
- Форма отправляется по HTTPS, отсутствуют смешанные http-запросы.
- Куки сессии выставлены с флагами `HttpOnly`/`Secure`/`SameSite`.
- Тайминг-атака: время ответа не должно явно отличаться для "email не существует" и "email существует, пароль неверный" (не давать возможность энумерировать пользователей по времени ответа).
